# ALGO ARENA

白と黒の数字カードを推理する、2人用のオンライン対戦サイトです。Blokeeのゲスト参加、ルーム一覧、観戦、持ち時間、レーティングと成績の導線を参考に、独自の画面と対戦エンジンを実装しています。

## できること

- ゲスト参加、名前変更、登録アカウントへの移行とログイン
- 人間同士のレート対戦・カジュアル対戦、招待ルーム、AI練習
- 相手に伏せ札を送らないサーバー側の配札・判定
- 5分＋5秒／10分＋10秒の時計、投了、時間切れ、再接続
- 公開対局の観戦、ルーム内チャット、対戦履歴、実データのランキング
- 初期1500、K=40のElo。AI・カジュアル戦はレートに影響しません

模擬対戦、固定の正解、架空のオンライン人数・ランキングは使用していません。対戦相手がいない場合は待機状態を表示します。

## 起動

Node.js 22以上を使います。実行時の外部サービスやnpmパッケージは不要です。

```bash
npm start
```

[http://localhost:4173](http://localhost:4173) を開きます。2人対戦の確認には異なるブラウザまたはプライベートウィンドウを使ってください。ローカルの記録は `server/data/arena.json` に保存されます。

環境変数:

| 名前 | 用途 |
| --- | --- |
| `PORT` | ポート。既定は4173 |
| `HOST` | 待受アドレス。既定は0.0.0.0 |
| `DATA_FILE` | 保存先。永続ディスク上の絶対パスを推奨 |
| `PUBLIC_ORIGIN` | HTTPSプロキシの背後で動かす場合の公開オリジン。例 `https://example.com` |

## 公開

このリポジトリはフロントエンドとAPIを同じサーバーから配信します。GitHub Pagesはサーバーを実行できないため、**Pagesだけではオンライン対戦は動きません**。

Node.jsサーバーはDockerやNode.js対応ホスティングで実行できます。Dockerでは `/data` を永続ボリュームにマウントしてください。`render.yaml` は起動用の例です。無料の一時ディスクでは再起動時に記録が消えるため、継続運用には永続ストレージが必要です。

Sites版はCloudflare WorkerとD1を使います。`.openai/hosting.json` の既存IDを保ち、公式Sitesワークフローで保存・デプロイします。SQLスキーマは `db/schema.ts`、生成済みマイグレーションは `drizzle/` にあります。リクエスト処理中にテーブルを作成しません。

```bash
npm ci
npm test
npm run build
```

`dist/server/index.js` に画面とAPIがまとまり、`dist/.openai/` にホスティング設定とマイグレーションが出力されます。

## ルールとレート

0〜11を白黒各1枚、合計24枚使用します。各自4枚から始め、数字の昇順、同数なら黒→白の順で並べます。手番の最初に1枚引き、相手の伏せ札を指定して数字を当てます。失敗したら引いたカードを公開して手番を終えます。成功後は続けて当てるか、ステイして引いたカードを伏せて加えます。相手の札をすべて公開すれば勝ちです。

本サイトはチップなし、1ラウンドを1対局とします。山札が尽きた後もアタックを行い、失敗したら自分の左端の伏せ札を公開します。これは本サイトの追加ルールです。時計の加算は有効なアタックとステイの各操作に適用します。通信切断中も時計は進みます。

Eloの期待勝率は `E = 1 / (1 + 10 ** ((相手レート - 自分レート) / 400))`、増減は `round(40 * (結果 - E))` です。片方の増減を計算してもう片方を逆符号とし、ゼロサムで1回だけ確定します。同レートの勝敗は±20です。投了と時間切れも勝敗に含めます。Expert 1700、Master 1800、Grandmaster 1900の表示区分を採用しています。

## 実装と検証

- `shared/engine.js`: シリアライズ可能なルール・可視情報だけで判断するAI
- `shared/api.js`: 認証、ルーム、時計、レート確定、チャット、入力制限
- `server/`: Node.js配信と一時ファイルからの置換による保存
- `worker/`: D1でのバージョン付き比較更新。大きな記録はgzipで圧縮
- `tests/`: ルール、秘匿情報、同時操作、保存、時計、レート、認証のテスト

各操作は保存済みバージョンとの比較更新で確定し、競合した場合は最新状態から再実行します。公開APIはプレイヤーごとの安全な盤面だけを返します。ゲストのセッションはこのブラウザに保存され、別端末へ持ち運ぶには登録アカウントを使います。

小規模なコミュニティ向けの初版です。1つの状態を比較更新する構成のため、大規模な同時接続にはルーム単位のストレージ分割が必要です。ゲストの複数作成や談合を完全に防ぐ本人確認機能はありません。

調査で確認できた事実と採用した仕様の違いは [docs/reference-notes.md](docs/reference-notes.md) に記録しています。
